### 本轮实测发现并修复的 4 项缺陷（全部实测复现，非阅读推断）
- **D1（阻塞）CORS 白名单缺 80 端口**：前端容器发布在 `:80`，实测 `Origin: http://localhost` 被拒，
  而 `http://localhost:8080` 等返回 200 → 默认 `docker compose up` 后页面能开、API 全挂。
  已在 compose 默认值与两份 `.env.example` 补 `http://localhost` / `http://127.0.0.1`。
- **D2（阻塞）nginx `/api` 反代与后端前缀不匹配**：后端**没有** `setGlobalPrefix('api')`，
  旧配置 `proxy_pass` 无尾斜杠会原样转发 `/api/**` → 必然 404。
  这是"看代码容易漏、跑起来立刻炸"的典型。
  改法：`location /api/` + `proxy_pass http://backend:3000/`（尾斜杠配对 ⇒ 剥前缀），
  并单独 `^~ /api/docs` 原样透传（Swagger 自带 `api` 前缀，不能被剥；前缀更长者优先）。
  用等价前缀代理实测：`/api/health/live`→200、`/api/user/list`→401、`/api/docs`→200；
  直连后端 `/api/user/list`→404（反证必须剥前缀）。
- **D3（重大，安全/成本）限流可被一行请求头绕过**：`rate-limit.guard` 直接读 `x-forwarded-for`。
  实测：固定伪造值第 21 次触发 429，但**每次换伪造值连打 40 次全部放行（0 × 429）**。
  修法：改用 `request.ip`（Express 仅在 `app.set('trust proxy', …)` 允许时才采信该头），
  新增 `TRUST_PROXY` 配置**默认关闭**。修复后 429 × 5；
  `TRUST_PROXY=1` 时取 nginx `$proxy_add_x_forwarded_for` 追加的**真实 IP**，伪造段无效。
  → **经验：任何"从请求头取客户端 IP"的代码都要先问"这头客户端能不能伪造"。**
- **D4（中）** ① CORS 拒绝用裸 `Error` → 被归一化成 **500**（把客户端拒绝记成服务端故障）；
  改抛 `AppError(FORBIDDEN)` → 403。② 生产无条件注册 Swagger（枚举全部端点含管理端）
  → 默认仅非生产注册，`ENABLE_SWAGGER=true` 放开。③ 无安全响应头、下发 `X-Powered-By`
  → 新增零依赖中间件（nosniff / DENY / no-referrer，生产加 HSTS；开发不下发 HSTS 以免打断 http）。
  ④ 后端镜像 HEALTHCHECK 打慢探针 `/health` → 改 `/health/live`。

### 方法论沉淀（值得复用）
1. **评估要看"默认路径"，不是"能配通的路径"**：D1/D2 都只在"用户按文档默认部署"时才炸。
2. **安全防护必须做"对抗性实测"**：限流不是"看它拦没拦"，而是"换个身份还能不能刷"。
3. **改代理/网关配置时用等价最小代理做路由级验证**：沙箱起不了 docker，
   就写一个几十行的前缀剥离代理复刻 nginx 规则，把"推理正确"变成"实测正确"。
4. 沙箱里 `bash` 的 `head/tail` 等 coreutils 不可用，一律用 `node -e` + 绝对路径；
   管道会被 shim 打断。
