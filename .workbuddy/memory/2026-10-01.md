## 自检问题逐项闭环 + 上线加固（同日第三轮，提交 577f03a）
- 自检报告 20 项已全部闭环，提交 `577f03a`（46 文件 / +1499−137）。关键修复：
  - **P0-1 RBAC**：`roles.guard.ts` 重写为全局守卫（`app.module.ts` 注册为第 2 个 APP_GUARD），**无 `@Roles` 元数据一律拒绝**（默认拒绝，避免"漏加装饰器 = 放行"）。实测 student 调 `/user/list`、`/user/create` 均 403。
  - **P0-2**：`jwt.strategy.validate` 与 `global-auth.guard` 统一 `req.user = {sub,userId,username,roles}`（只改守卫会变成全员 403，两处必须同步）。
  - **P1 15 分钟时效**：实测 expires_in=900（此前 604800 实际未生效）。
  - **P1 并发刷新互踢**：宽容窗口 `REFRESH_REPLAY_GRACE_SECONDS=30` + `RedisCacheService.setIfAbsent` 单飞锁，并发 10 次刷新全部拿同一令牌。
  - **P1 登录误判过期**：前端 `request.ts` 加 `SKIP_REFRESH_URLS` 白名单。
  - **P1 登录锁定连坐**：锁定判定只看账号维度（此前 `Math.max(byUser,byIp)` 导致共享 IP 用户互相连坐），IP 仅观察；`status()` 改为存到期时间戳以真实递减。
- 新增门禁：`scripts/verify-all.cjs`（后端 tsc+jest / 前端 vue-tsc / 密钥 / 日志卫生，一条命令）、`scripts/auth-probe.cjs`（真实 HTTP 认证集成探针）、`scripts/log-hygiene-scan.cjs`。
- **密钥扫描豁免机制**：`secret-scan.cjs` 增加 `ALLOWLIST`（按 **文件+规则** 精确匹配，仅豁免测试夹具），命中豁免仍**显式打印**不静默丢弃；**不按目录排除测试文件**（否则真实密钥进 spec 就漏检）。
- **健康探针分离**（本轮新增）：`/health/live`（不碰任何依赖，2~5ms）vs `/health/ready`（只判关键依赖 Mongo + 已配置但不可达的 Redis，不就绪返回 503）；SymPy/Neo4j 属可降级依赖**刻意不查**。
  docker-compose backend healthcheck 从 `/health` 切到 `/health/live` —— 原因是 `/health` 会同步查 SymPy（3 次重试 × 5s）最坏 15s+，超过探针 timeout 会把可降级抖动误判为"进程已死"引发重启循环。
- **`TransformInterceptor` 的 `code` 与 HTTP 状态码对齐**（此前恒 200；`/health/ready` 返回 503 时 body 里仍是 `code:200`，按 body 判定的客户端会读错）。2xx 仍记 200（保持 POST 201 的既有语义），仅 ≥400 透传。
- **CI**：`.github/workflows/verify.yml`（静态门禁 + 带真实 Mongo/Redis 服务的认证集成作业，复用本地同一份脚本）。
- 验证证据：jest **16 套件 / 137 用例**全绿；verify-all **5 项全绿**；`self-check --mode local --full` **38/38 通过**；生产模式实测 401 响应仅 6 字段（无 stack/details）。
- 经验：① 新增"未就绪返回非 2xx"的接口时，务必检查全局拦截器的 `code` 是否与状态码一致；② 存活探针绝不能查可降级依赖；③ 给密钥扫描加豁免要"文件+规则"精确匹配且打印出来，不要整体排除目录。
