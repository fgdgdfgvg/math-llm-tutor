# 部署就绪清单

> 适用版本：2026-10-02（第二轮认证/安全改造 + 自检闭环后）
> 目标：把系统作为**可部署的工程原型**交付——核心链路可用、关键流程有验证证据、配置可校验。

## 一、组件与端口

| 组件 | 目录 | 端口 | 说明 |
|---|---|---|---|
| 后端 API | `nestjs-backend` | 3000 | NestJS，`dist/main.js` 启动 |

启动（容器编排）：

```bash
docker compose up -d            # 会按 ./nestjs-backend/.env 注入配置
docker compose ps               # 全部 healthy 即可
```

本机开发：`npm run self-check:full`（自动起后端 + SymPy + 前端并跑完整自检）。

## 二、必须配置的环境变量

完整清单见 `.env.example`（根目录）与 `nestjs-backend/.env.example`。**只提交 .env.example，真实 .env 已在 .gitignore 中。**

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `JWT_SECRET` | ✅ | — | 生产必须 ≥32 字符且非默认值（启动期校验） |
| `MONGODB_URI` | ✅ | — | 含库名（`.../math_llm_tutor`） |
| `CORS_ORIGIN` | ✅（生产） | — | 逗号分隔白名单；**生产缺失直接拒绝启动** |
| `JWT_EXPIRATION` | 建议 | `15m` | access token 时效；**生产 >1h 拒绝启动** |
| `JWT_REFRESH_TTL` | 建议 | `30d` | refresh token 时效（服务端存储、轮换） |
| `REFRESH_REPLAY_GRACE_SECONDS` | 建议 | `30` | 重放宽容窗口（并发刷新不互踢） |
| `LOGIN_MAX_FAILURES` / `LOGIN_LOCK_SECONDS` | 建议 | `5` / `900` | 登录失败锁定 |
| `REDIS_URL` | 多实例必填 | — | 缺失时降级为进程内内存（单实例可用，多实例会不一致） |
| `TRUST_PROXY` | 反代部署必填 | 空（=不信任） | 见下方"反向代理信任"说明；**不能无条件信任 `X-Forwarded-For`** |
| `ENABLE_SWAGGER` | 可选 | 空（生产关闭） | 生产默认不注册 API 文档；内网确需开放时设 `true` |
| `API_BASE_URL` | 前端构建期 | `/api` | 前端请求基址；默认走 nginx 同源反代（无跨域） |
| `SYMPY_SERVICE_URL` / `SYMPY_INTERNAL_TOKEN` | 建议 | — | 符号计算服务地址与内部令牌 |
| 各家 `AI_*_API_KEY` | 可选 | — | 缺失时智能体降级为本地规则引擎 |

**反向代理信任（安全敏感）**：`req.ip` 依据 Express 的 `trust proxy` 解析。
默认**不信任** `X-Forwarded-For`——该头客户端可任意伪造，无条件采信等于取消限流
（实测：随机伪造该头可让 LLM 限流 40/40 全部放行）。部署在 nginx/网关之后时必须显式开启
`TRUST_PROXY=1`，此时限流键取的是 nginx 用 `$proxy_add_x_forwarded_for` 追加的**真实客户端 IP**，
客户端自行塞进该头的值不会生效。compose 已默认 `TRUST_PROXY=1`，其前提是后端端口只绑 `127.0.0.1`。

## 三、上线前验证门禁（一条命令）

```bash
npm run verify
```

包含 5 项，全绿才可交付：

1. 后端类型检查 `tsc --noEmit`
2. 后端单元测试 `jest`（16 套件 / 137 用例）
3. 前端类型检查 `vue-tsc --noEmit`（当前 0 错误）
4. 密钥扫描 `scripts/secret-scan.cjs`（0 检出；测试夹具走 ALLOWLIST 精确豁免并显式打印）
5. 日志卫生扫描 `scripts/log-hygiene-scan.cjs`（禁止整体打印 error 对象）

集成自检（需要 MongoDB / SymPy / 可选 Redis / Neo4j）：

```bash
node scripts/self-check.cjs --mode local --full      # 会先自动重新构建 dist
node scripts/auth-probe.cjs                  # 认证与授权专项探针（RBAC/轮换/锁定/信封）
npm run verify:probe                         # 部署加固探针（自带进程与端口，无需外部依赖）
```

> `verify:probe` 覆盖的是"上线后才暴露、单测覆盖不到"的行为：限流来源不可伪造、
> 安全响应头、CORS 拒绝语义、生产环境 Swagger 收敛、存活/就绪探针语义。共 15 项。
>
> 更完整的上线评估（评估标准、逐维度结论、差距清单、优先级）见
> [`docs/可部署性评估报告.md`](./可部署性评估报告.md)。

> 注意：`self-check` 检测到"运行中的后端是旧构建"时会拒绝出具结论（避免验证旧代码），
> 需要先 `node scripts/self-check.cjs --stop` 或换端口 `--port 3101`。

### CI 自动化（`.github/workflows/verify.yml`）

与本地同一份脚本，避免"本地绿、CI 红"的双份逻辑漂移：

- **static-gates**：`npm ci`（后端 + 前端）→ `node scripts/verify-all.cjs`，即上面 5 项门禁。
- **auth-integration**：起真实 Mongo 7 + Redis 7 服务容器 → `npx tsc` 编译 → 起后端 →
  轮询 `/health/ready` 确认就绪 → 跑 `auth-probe.cjs` 覆盖 RBAC 越权、refresh 轮换幂等、
  令牌时效、登录锁定。SymPy/Neo4j 相关数学正确性仍由本地 `self-check` 覆盖
  （拉额外镜像会让 CI 又慢又脆）。

## 三点五、健康探针（编排器对接）

| 端点 | 用途 | 依赖 | 期望响应 |
|---|---|---|---|
| `/health/live` | **liveness** | 无（纯进程存活） | 恒 `200`，毫秒级 |
| `/health/ready` | **readiness** | Mongo、Redis（仅关键依赖） | 就绪 `200` / 不就绪 `503` |
| `/health` | 人工排查（全量视图） | Mongo/SymPy/Neo4j/缓存/系统指标 | `200`，含各依赖状态与内存 CPU 指标 |
| `/health/detailed` | 全量 + 库表计数 | 同上 | `200` |

判定口径（与业务侧真实降级能力一致）：

- **关键依赖**：Mongo、**已配置但不可达**的 Redis → 判不就绪（`503`），编排器把实例摘出负载均衡。
- **可降级依赖**：SymPy / Neo4j → 后端有规则引擎与内存图兜底，**不摘流量**，因此 `/health/ready`
  刻意不调用它们。

> 为什么不能拿 `/health` 当 liveness：它会同步探测 Mongo + SymPy（内部 3 次重试 × 5s 超时）+ Neo4j，
> 单次最坏 15s+；而 liveness 探针超时通常只有 1~3s。SymPy 一慢就会被误判成"进程已死"→ 容器反复重启，
> 把可降级的抖动放大成真故障。docker-compose 的 backend healthcheck 已切到 `/health/live`。

自测证据（本轮实测）：

```
/health/live    HTTP 200   2~5ms      （Redis 死端口时仍 200，证明探活不受依赖影响）
/health/ready   HTTP 200   3ms       （依赖正常）
/health/ready   HTTP 503   7ms       （REDIS_URL 指向不可达端口，body.code 同为 503）
```

## 五、已知限制（部署前需知）

1. **多实例必须配 Redis**：refresh token、登录限流、题目缓存都走 `RedisCacheService`；未配置时降级为进程内内存，多实例会出现"在 A 登录、打到 B 刷新失败"。
2. **refresh token 存于客户端 Storage**：小程序/App 无 HttpOnly Cookie 可用，属平台折中；H5 独立部署可改 SameSite Cookie。
3. **第二套前端 `math-tutor-prototype` 未接入 refresh**：登录路由已修正为 `/user/login`，但 access token 过期后需重新登录；建议正式交付前移除或改造。
4. **`python-asr-service/` 是空壳**（无源码），语音输入走前端 `uni.stopRecord` + 后端多模态接口；建议删除该目录以免误判。
5. **长任务同步返回**：多智能体求解为串行同步调用（数十秒），尚未任务化 + SSE；生产环境建议加网关超时≥60s 或后续改造为异步任务。
