# 可部署工程原型评估报告

> 评估对象：高等数学 LLM 智能教育系统（`math_llm_tutor`）
> 评估日期：2026-10-02
> 评估基线：`577f03a`（自检 20 项闭环后）+ 本轮部署加固改动
> 评估方式：**以实测为准**——所有结论均由真实进程、真实 HTTP 请求、真实构建得出，不采信"代码看起来对"

---

## 一、结论

**已达到"可部署工程原型"级别。**

判定成立，但**部署前必须完成 2 项前置动作**（均为环境/人工项，非代码缺陷）：

| 编号 | 前置动作 | 原因 |
|---|---|---|
| PRE-1 | 在性能正常的机器或 CI 上跑通一次前端 H5 生产构建（`npm run build:h5`） | 本沙箱环境下该构建**挂起**：进程存活 33 分钟、`Compiling...` 后无任何输出、`uniapp-frontend/dist` 零写入（仍是 3 天前的旧产物）、`node_modules/.vite` 未更新、内存稳定在 806MB 不再变化 —— 判定为卡住而非在编译，已终止。因此未取得产物证据；已在 CI 加入该构建门禁（含产物存在性校验），但需真实跑一次方可确认 |
| PRE-2 | 到服务商后台轮换历史上曾明文入库的 3 组 AI 密钥 | 代码侧已脱敏并加扫描门禁，但**已泄露的密钥必须作废**，脚本无法代办 |

> 结论对比：**本轮修复前，判定为"未达到"**。评估过程中实测出 4 个阻塞/重大缺陷（详见第四节），
> 其中 3 个会让默认部署路径不可用或成本防护失效。这 4 项现已全部修复并实测验证。

## 二、评估所依据的主要标准

"可部署工程原型"= **能在一台干净机器上按文档启动、核心链路真的能用、坏掉时看得见、且每次改动都能自证没退化**。
拆成 7 个维度，每维度给出可判定的通过线：

| # | 维度 | 通过线（可判定） |
|---|---|---|
| 1 | 核心功能链路 | 主链路（题目 → 多智能体 → SymPy → 步骤+答案）端到端跑通，且回答正确 |
| 2 | 部署路径可复现 | 有一条命令或一份编排能拉起全部组件；配置全部来自环境变量；无人工临时步骤 |
| 3 | 关键流程有真实验证 | 认证/授权/写入等关键流程经**真实 HTTP 请求**验证通过，不靠单测代替 |
| 4 | 可观测与可诊断 | 健康探针语义正确；结构化日志带 traceId；生产环境不泄露堆栈 |
| 5 | 安全基线 | 密钥不入库且可扫描；鉴权默认拒绝；CORS 显式白名单；限流**不可被客户端绕过**；错误响应不泄露内部细节 |
| 6 | 回归门禁 | 一条命令自证无退化（类型/单测/密钥/日志卫生/构建），且已接入 CI |
| 7 | 无阻塞级已知缺陷 | 不存在"默认路径跑不通"或"安全防护可被一行请求头绕过"这类缺陷 |

## 四、本轮实测发现的差距（修复前）

全部为**实测复现**，非代码阅读推断。

| 编号 | 级别 | 现象（实测） | 影响 | 修复 | 验证 |
|---|---|---|---|---|---|
| **D1** | 🔴 阻塞 | 复刻 compose 默认 `CORS_ORIGIN` 后请求带 `Origin: http://localhost`（前端容器发布在 `:80`，正是用户实际访问的地址）→ **被拒绝**；而 `http://localhost:8080` 等在白名单内则 200 | 默认 `docker compose up` 后**页面能打开、所有 API 调用全挂**——开箱即用路径直接不可用 | 默认白名单补 `http://localhost`、`http://127.0.0.1`；改为同源反代后浏览器根本不产生跨域 | 探针【3】白名单来源 200 + ACAO 正确；`http://localhost` 现被放行 |
| **D2** | 🔴 阻塞 | nginx `location /api { proxy_pass http://backend:3000; }`（无尾斜杠）会把原 URI 原样转发，但后端**没有** `setGlobalPrefix('api')`（全仓库 grep 无匹配）→ 走同源反代的 `/api/**` 必然 404 | 同源反代方案不可用，前端只能直连后端端口，进而触发 D1；后端端口被迫对外暴露 | nginx 改为 `location /api/` + `proxy_pass http://backend:3000/`（尾斜杠配对 → 剥掉 `/api` 前缀）；并单独放行 `/api/docs`（Swagger 自带前缀，不能被剥）；compose 前端基址改 `/api` 同源；后端端口改绑 `127.0.0.1` | **已用等价前缀代理实测**：`/api/health/live`→200、`/api/user/list`→**401**（路由命中、需鉴权）、`/api/docs`→200（透传正常）；直连后端 `/api/user/list`→**404**，反证后端确无 `api` 前缀、必须由代理剥掉 |
| **D3** | 🔴 重大（安全/成本） | `rate-limit.guard.ts` 直接读 `x-forwarded-for` 头。实测：固定伪造值第 21 次触发 429（限流本身有效），但**每次换一个伪造值连打 40 次全部放行（0 次 429）** | LLM 接口（`/agents/solve` 等，5 分钟 20 次）的**成本防护完全可被一行请求头绕过**，任何人可无限刷模型额度 | 改用 `request.ip`（Express 仅在 `app.set('trust proxy', …)` 允许时采信该头，默认不信任）；新增 `TRUST_PROXY` 配置，默认关闭 | 探针【1】默认模式下伪造 IP 连打 25 次 → **429 × 5**（修复前 × 0）；探针【2】`TRUST_PROXY=1` 下客户端伪造段被忽略（取 nginx `$proxy_add_x_forwarded_for` 追加的真实 IP）→ **429 × 5**，同真实 IP 再来 25 次 → 429 × 25 |
| **D4** | 🟠 中（安全/可观测） | ① CORS 拒绝用裸 `Error` → 被全局过滤器归一化为 **500**，把"客户端来源不被允许"记成服务端故障，污染 5xx 监控与错误日志；② 生产环境**无条件注册 Swagger**（`/api/docs`），完整枚举含管理端在内的全部端点；③ 无安全响应头，Express 默认下发 `X-Powered-By`；④ 后端镜像 HEALTHCHECK 打慢探针 `/health`（最坏 15s+ > timeout 10s），会把可降级的 SymPy 抖动误判成"容器已死" | 监控误报；公网暴露完整攻击面清单；缺 nosniff/防嵌入等基础防护 | ① 改抛 `AppError(FORBIDDEN)` → **403**；② Swagger 默认仅非生产注册，`ENABLE_SWAGGER=true` 显式放开；③ 新增零依赖 `securityHeaders()`（nosniff / X-Frame-Options DENY / Referrer-Policy no-referrer，生产加 HSTS，移除 X-Powered-By）；④ 镜像 HEALTHCHECK 改 `/health/live` | 探针【3】：CORS 拒绝 **403** 且响应无 `stack`；安全头齐备；**生产 HSTS 已下发、Swagger 404**；探针【4】：`ENABLE_SWAGGER=true` 后 Swagger 可访问 |

## 五、仍在的差距与不足（未闭环）

| 项 | 状态 | 为什么不阻塞原型 | 预期结果 |
|---|---|---|---|
| PRE-1 前端 H5 生产构建未取得产物证据 | ⏳ 环境受限（进程挂起，已终止） | `vue-tsc` 0 错误；构建进程存活但零文件写入。但**构建成功与否与类型检查是两套判定**，不能相互代替 | 已在 CI 加 `npm run build:h5` + 产物存在性校验；需在正常环境跑通一次 |
| PRE-2 3 组历史泄露密钥未轮换 | ⏳ 人工 | 代码侧已脱敏 + 门禁拦截，新增泄露会被 `npm run verify` 挡住 | 服务商后台作废旧密钥并更新 `.env` |
| 多实例部署必须配 Redis | 📌 已知限制 | refresh/限流状态走 `RedisCacheService`，未配置时降级为进程内内存，单实例可用；`/health/ready` 会在"已配置但不可达"时返回 503 显式提示 | 多实例前配置 `REDIS_URL` |
| 长任务同步返回（数十秒） | 📌 已知限制 | 已把超时链路对齐（前端 axios 180s / nginx `proxy_read_timeout` 300s / SymPy 预算 20s），单机能跑通 | 改造为异步任务 + SSE 推送 |
| 第二套前端 `math-tutor-prototype` 未接入 refresh | 📌 待清理 | 登录路由已修正；access 过期需重新登录。非主交付路径 | 交付前移除或改造 |
| 掌握度量纲存在 0~1 与 0~100 混用 | 📌 待统一 | 只影响推荐/画像的数值口径，不影响可用性（`admin` 用 `>=0.8`，`assessment` 用 `*100`，`correctRate` 又按 0~100） | 统一口径并补调用点测试 |
| 重复实现：两套前端 / 两份 sympy / 三套公式渲染器；巨型文件；`python-asr-service` 空壳 | 📌 技术债 | 属结构性重构，与"保持架构不变"约束冲突 | 独立立项逐步收敛 |

## 八、复现命令

```bash
# 1) 静态门禁（类型 / 单测 / 密钥 / 日志卫生）
npm run verify                      # 5 项全绿才可提交

# 2) 真实 HTTP 探针（需后端在运行；auth-probe 用 BASE_URL 指定入口）
npm run auth:probe

# 3) 部署加固探针（自带进程与端口，无需外部依赖）
npm run verify:probe

# 4) 完整集成自检（需 MongoDB / SymPy，可选 Redis / Neo4j）
node self-check.cjs --mode local --full

# 5) 容器编排（需 Docker；本沙箱不可执行，需在正常环境确认）
docker compose up -d && docker compose ps
```
