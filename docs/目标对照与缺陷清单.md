## 三、缺陷清单（按影响程度分级）

### A. 阻断性问题 —— 照文档执行必然失败

**A1｜`scripts/start-all.sh` 的 4 个子缺陷**（一键启动是文档给出的**第一条**命令）

| 子项 | 现象 | 根因 | 状态 |
|---|---|---|---|
| A1-1 | 后端健康检查打 `http://localhost:3000/api/health`，后端**没有** `setGlobalPrefix('api')`（全仓 grep 无匹配，上轮已实测直连 `/api/user/list` → 404）→ 该 `curl` 永远失败，脚本必然误报"后端未就绪" | 从 nginx 同源代理（前缀由代理剥）照搬到直连场景，前缀没跟着变 | ✅ 已修：改打 `/health/live` 并按 HTTP 码判定 |
| A1-2 | 启动横幅打印 `MongoDB: mongodb://<user>:<password>@<host>:27017` 形态的连接串，即 **root 账号 + 默认弱口令**直接进终端与日志 | 横幅照抄连接串模板，未做脱敏 | ✅ 已修：改为占位符 + 提示口令见 `.env` |
| A1-3 | 硬编码 `docker-compose`（v1 命令），只装 Docker v2 的机器上不存在 → 脚本中断 | 依赖 v1 CLI | ✅ 已修：加 `DOCKER_COMPOSE` 探测（v2 `docker compose` 优先，回退 v1） |
| A1-4 | 步骤编号 `[1/7]…[4/7]` 与 `[5/8]…[8/8]` 混用 | 改脚本时漏改 | ✅ 已修：统一为 `/8` |

**影响范围**：仅 `scripts/start-all.sh`；不涉及后端/前端运行时行为，风险极低。
**根因共性**：这个脚本是"文档承诺"与"真实部署形态"脱节的产物——它成文于"后端有 `/api` 前缀""用 docker-compose v1"的假设，之后架构变了却没同步。

### B. 重要功能缺失

| 编号 | 缺陷 | 根因 | 状态与原因 |
|---|---|---|---|
| **B1** | `pages.json` 缺 4 项 tabBar（目标 5.1.3 明确要求首页/场景/知识/进度四个入口） | 只按"页面可达"实现，未按目标补底部导航 | **推迟**：tabBar 需 `static/*.png` 图标资源（当前不存在），且本沙箱无法跑前端构建（见风险 R1），盲改可能导致导航不可用且无法验证 |
| **B2** | API 响应压缩未做（目标 11.3.3 中优先级） | 未引入 `compression`，nginx 侧也未开 gzip | **推迟**：预算不足（见第五节）。已确定零依赖方案（后端 zlib 中间件，可实测），下一轮实施 |
| **B3** | 掌握度量纲靠"数值大小"猜：前端 `toPercentMastery()` 用 `0 < v <= 1 → v*100` 启发式 | 后端同一概念在不同接口返回不同量纲（`assessment` 0–100、`learning`/`admin` 0–1），前端在渲染层做兼容 | **推迟**：正确做法是**在 API 契约层统一**并显式声明，而不是继续在渲染层猜。属跨模块改动，需先定契约，超出本次预算 |
| **B4** | 第二套前端 `math-tutor-prototype` 未接入 refresh 续期 | 早期原型未跟进认证改造 | **推迟**：非主交付路径，建议直接移除而非改造 |
